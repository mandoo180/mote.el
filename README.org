#+TITLE: mote.el
#+OPTIONS: toc:nil

One command keeps a personal notes directory in sync with a git remote.

* Why

Notes want version control but not a version-control workflow.  ~mote~
gives you a single command.  It commits what changed, merges what the
remote has, resolves conflicts on its own and pushes.  It never asks a
question, and every decision it makes stays in the history, so anything
it got wrong can be reverted.

* Install

#+begin_src emacs-lisp
(use-package mote
  :vc (:url "https://github.com/mandoo180/mote.el" :rev :newest)
  :commands (mote-sync)
  :custom
  (mote-root (expand-file-name "~/notes"))
  (mote-remote "git@github.com:you/notes.git")
  :bind ("C-c n S" . mote-sync))
#+end_src

* Use

~M-x mote-sync~.  That is the whole sync interface.

The first run turns ~mote-root~ into a git repository, seeds a
~.gitignore~ and connects ~mote-remote~.  Later runs commit, merge and
push.  Everything happens in the background; the echo area reports the
outcome and =*mote-log*= holds every git command and its output.

* Conflicts

When both machines changed the same file, the side whose commit is more
recent wins, file by file.  Deleting counts as a change: a newer
deletion beats an older edit.  The losing version is still in the
history, and the merge commit names the winner:

#+begin_example
mote: merge origin/main (latest-wins: 2 files)

resolved by newer commit time:
  local   denote/foo.org   2026-08-26 13:40
  remote  inbox/bar.org    2026-08-26 13:44
#+end_example

* Self-healing

An interrupted run leaves nothing for you to fix.  The next ~mote-sync~
aborts a leftover merge, rebase or cherry-pick, removes a stale
~index.lock~, reattaches a detached HEAD, supplies a committer identity
when the repository has none, merges unrelated histories, and retries a
push the remote rejected.  A network failure keeps the local commit and
gives up quietly.

~mote~ never runs ~git reset --hard~, ~git clean~ or a forced push.

* Theme export

~M-x mote-export-theme~ writes the faces of the selected frame to a
theme file for the Mote phone app, ~.mote/themes/ID.toml~ under
~mote-root~.  It asks for the id, offering the first enabled theme's
name lower-cased with every character other than a letter, digit or
hyphen turned into a hyphen (~emacs~ when no theme is enabled), and
asks again before overwriting an existing file.

Then run ~M-x mote-sync~, sync on the phone and pick the theme there
with the app's ~load-theme~ command.  The app keeps one theme for light
mode and one for dark; the file's ~kind~ follows this frame's
background mode and decides which of the two ~load-theme~ sets.

The file holds final values only.  Emacs faces inherit through faces
the app does not know, so ~mote-export-theme~ follows inheritance here
and writes what it resolves to, with an empty ~inherit~ list.  What a
face leaves unspecified all the way is written as ~"unspecified"~,
which the app reads as Emacs does: where several faces cover the same
text, as a heading and a bold word in it, the faces beneath show
through, and alone the default face's value shows.  The cursor
contributes only its own background, the caret colour.  Colours become
~#RRGGBB~, weights fold to bold or normal, slants to italic or normal,
underline and overline to their colour, or to on or off when they
have none, and strike-through to on or off, all without style.  A relative height, such as the 0.8 org-modern gives
its labels, is written as it is; an absolute one is left out, because the
app only scales text.  A box is written with its line width and
colour, without its style.  An inverse-video face is written with its
foreground and background swapped, the colours Emacs draws it in, and
with inverse video off, so that the app does not swap them again.
When org-modern is on, its label faces carry an explicit pixel box, and
that box comes along with the theme; the app's ~org-modern-label-border~
then does not apply to that theme.  Exports made before 0.4.0 from a
desktop with org-modern on should be redone, or the labels lose their
background on the phone.  Faces of packages this Emacs has not loaded
yet (open a Markdown file first) are left out, and the app fills them
from its own defaults; Org's own faces are not among them, because
exporting always loads Org for the probes below, whether or not you
opened an Org file this session.  An older Mote app warns about each
~"unspecified"~ line and fills it from its own theme instead.  An app
older than Mote plan 25 also warns about each ~height~,
~inverse-video~ and ~box~ line.  One older than
Mote plan 26 warns about each ~overline~ line and each coloured
underline.

Org keywords, tags, checkboxes, the done headline, the document title
and strike-through are read differently: ~mote-export-theme~ fontifies
a small Org text in Org mode, with your hooks, and writes the face each
of them is drawn with, so packages such as org-modern and settings such
as ~org-todo-keyword-faces~ come along.  Where Emacs drew one over the
heading instead of merging with it, what it leaves unspecified is
written as the default face's value, so the heading does not show
through on the phone either.  If Org fails, those faces are read by
name and a message says so.  Only faces travel: the app draws bullets,
hidden markers and labels itself, from the ~[org]~ table of its
~.mote.toml~, and takes their colours from the faces written here.

Export from a graphical frame.  A terminal frame still writes the
file, but themes pick terminal colours there, which may only
approximate the graphical ones.

* Options

| Variable                 | Default          | Meaning                                    |
|--------------------------+------------------+--------------------------------------------|
| ~mote-root~              | ~~/mote-sync~    | Notes directory and repository root        |
| ~mote-remote~            | ~nil~            | Remote URL; nil keeps the repo local only  |
| ~mote-branch~            | ~"main"~         | Branch to synchronise                      |
| ~mote-gitignore~         | see source       | Lines seeded into a new ~.gitignore~       |
| ~mote-push-retry-limit~  | ~3~              | Retries after a rejected push              |
| ~mote-log-buffer~        | ~"*mote-log*"~   | Buffer collecting git output               |
